## What is replayed and what is not

- Same replay as `rescore-main-1029-2128`: stored `product_seen` and `speech` events re-emitted on the loop
  clock with their original offsets (`measure/c5_frozen.py`, caused by this run's own frames), frames from the
  stored test1 frame sequence through the media process, comments and the scripted shop of the offline C5
  scenario, one loop, no vision call. `app/`, `worker/` and `orders/` are those of `f2c2dba`.
- New in this run: the session is bound. The worker child reports `"injected": "Runner(attachment_auth=...)"`,
  the media child `"injected": "source bearer on httpx clients to http://127.0.0.1:8040"` (worker and media
  extracts below). `GET /api/sessions/<sid>/state` after the loop: `attachment_enabled: True`. With the binding
  on, `orders/handlers.on_labeled` / `on_message` return nothing (`orders/handlers.py:31-42`); orders come only
  from the attachment path (`app/attachment_orders.py`).
- Not replayed, because the stored observations do not hold it: the worker's own terminal read of every frame
  before each comment. The readiness evidence that the app checks (`app/attachments.py:309`
  `check_evidence`) needs, for every frame up to the comment, a record the authenticated worker produced itself
  — `product_seen` (with the cards it posted) or `no_product_seen` / `read_error`. In this 0 USD replay every
  vision read fails (no model client: `vision received 351, done 0, failed 351`), so every frame's record is
  `read_error` (`worker/runner.py:231`, `worker/attachments.py:67`); the stored `product_seen` events are
  posted by the media process, not read by the worker, so the worker cannot turn any frame into a
  `product_seen` record (`worker/attachments.py:72-84` needs a product_seen the worker posted). The contract
  forbids fabricating those records (`contracts/comment_attachment.md`, queue replacement / missing read
  remains a coverage hole), and this run fabricates none.
- A first attempt, `rescore-bind-1029-2212`, failed before the loop (`no frame from media in 120 s`): the media
  child's posts were refused with 401 because the bearer injection did not survive `runpy`. Fixed in
  `measure/c5_proc.py` (the client subclass carries the bearer); 2218 has 0 × 401 in the app access log.

## Why every attachment expired (read-only check on the stored session, `keviq_test`)

- The worker did evaluate: 211 readiness posts, every one answered 202 `pending` (`app/attachments.py:472`),
  then the app's timer expired each attachment at its 4 s deadline (`app/attachments.py:584`).
- The replayed `product_seen` events cite this session's frames: 11/11 have a `caused_by` that is a stored frame
  of the session, 11/11 `frame_ts_ms` equal that frame's `ts_ms`, source `replay`; 11/11 cards are caused by them.
- For 29 of the 30 order comments the required frame prefix (frames with `ts_ms` ≤ comment) contains at least
  one frame cited by a replayed `product_seen`; the exception is c5-1-001 (+3.5 s, before any product_seen, 0
  candidates). The worker's record for every such frame is `read_error` (every vision read failed), and
  `check_evidence` returns not-covered for a non-`product_seen` record on a frame that a stored `product_seen`
  cites (`app/attachments.py:358`). Not covered → no `ready` event → expiry. For c5-1-001 the snapshot at the
  comment holds no card, so there is nothing to attach either way.
- What the stored observations lack, therefore, is the authenticated worker's own frame reads: a
  `product_seen` record the worker produced for the frames the stored `product_seen` events cite (with the cards
  it posted), or `no_product_seen` records for the rest. A 0 USD replay cannot produce the first without a
  model client, and the run does not fabricate them. Measuring the #61 effect on references on this observation
  set needs either a paid replay in which the worker reads the frames itself, or a stored per-frame worker
  attestation that the 28 October observation did not record.

Reading: the binding path is exercised end to end (binding registered, bearer accepted, 30 attachments
recorded, candidate orders drafted, decision route enforcing the candidate selection), and the scripted
interventions drop to 1 because the legacy order path is off; but no attachment reached `ready`, so the
reference accuracy of #61 on this observation set is still unmeasured, not 0. The 0/28 is the cost of
missing worker frame reads, not a measurement of the reference logic.
